# Repair v3：失败候选的受控重新调查

## 目标与基线

用户已确认保留现有 CUDA 执行、证据、补丁与独立验证架构，优先改善失败后一直沿用首次诊断的问题。
开发基线为 `design/v2-operator-workflow@ab46153c0190aa73ed11305b4181a46dccf2be5f`；开发分支为
`feat/repair-v3-reinvestigation`。代码、配置与工作结果以 GitHub 为事实源；Tang 只用于真实 GPU 验证。

本次交付可显式启用的 `public-repair-v3`。默认 `public-repair-v2`、传统 diagnose、A–E 冻结评测保持原行为。
不在本次变更中添加经验库、通用任务恢复或替换 Agent 框架。

## 选择与理由

1. 每次失败都重跑初始调查：成本高，也可能反复看到已知缺陷，拒绝。
2. 对原始源码重新调查：实现较小，但无法解释修复后新出现的缺陷，拒绝作为完整 V3。
3. **按公开失败信号选择修订或重新调查失败候选**：采用。候选调查有独立源码、证据和行号作用域；
   最终补丁的基准始终为原始 `SourceSnapshot`。

## 行为契约

- 控制器依据公开检查分类；不声称分类器已经知道真实根因。
- 编译错误、单次运行错误直接修订；Sanitizer finding、公开功能错误，以及重复的非编译失败可触发重新调查。
- `max_candidates` 默认 3，范围 1–20；`max_reinvestigations` 默认 1，范围 0–3。
- 最后一个候选失败后不再调查，因为没有候选配额可使用调查结果。
- 达到重新调查上限后可继续使用已获得的诊断修订，仍受候选及总调用预算约束。
- 自检不可用、重新调查无法建立有效诊断、模型请求状态不明或预算不足时停止，并保存明确原因。
- 只有公开自检通过才执行一次现有严格独立验证；隐藏验证结果不反馈给模型。

## 源码与证据作用域

失败候选产生新的 `repair_reinvestigation` public 子运行，父级为原始诊断 run。
该子运行重新准备、编译、运行候选，随后进入既有 `AgentOrchestrator` 的受控工具循环。
所有事实、工具 findings 与 diagnosis citations 均绑定该子运行当前源码；不把候选证据写入原始 bundle。

上一轮诊断、其源码 hash、失败候选 hash 和公开自检反馈通过 `PublicRepairContext` 提供，标记为历史假设与
候选反馈，不能作为新诊断的合法引用。公开功能错误由控制器针对子运行真实输出重新计算，并绑定输出工件。
仅这种经过当前公开输出确认的错误允许 V3 在没有 Sanitizer finding 时结束调查；V2 的证据要求不变。

父运行原始 diagnosis 保持原源码语义；候选 diagnosis 以 source hash 和 run ID 另行记录，并作为下一轮
`revise_patch` 的当前诊断。模型同时收到失败候选全文及原始源码，补丁校验仍只接受针对原始源码的完整 replacement diff。

## 预算与错误处理

所有调查复用同一 provider、`LLMCallGate`、实际 `BudgetLedger` 和全程截止时间。
原始调查加全部重新调查共享已有采集上限：4 次 Sanitizer、3 次 RAG、38 个 agent steps、40 次模型调用和 600 秒。
每个候选的固定 self-check 是独立验证支出，由候选上限和相同总截止时间约束；分别记录其 Sanitizer 调用数，
不能把“调查最多 4 次”写成“整个 repair 总共最多 4 次”。

新调查开始时仅重新预留诊断与补丁的尾部调用，不清空调用数、deadline 或已使用的格式重试。
工具去重和 finish 动作按不同候选作用域处理；同一候选内仍拒绝无增益重复。
所有退出路径写回累计预算，后端工作区由 finally 清理。不新建模型 provider 来绕过 UNCERTAIN。

## 可观测性与验收

每轮保存候选、自检、决策、诊断作用域、重新调查 run、预算前后值及最终停止原因。
V3 模型调用使用独立 prompt version `public-repair-v3-2026-10-08-v1`；无 V3 上下文时旧 prompt/payload 保持一致。

验收覆盖：V2 回归；失败→调查→新诊断→原始基准修订；数值失败且 Sanitizer CLEAN；不同源码的 citation 隔离；
共享预算/截止时间/格式重试；上限与不可用停止；私有 canary 不流入模型；严格 verifier 只运行一次。
CPU 单元测试不能冒充 GPU 或模型效果证据；Tang 验证明确记录代码提交、实际工具、输入与结果。

## 效果解释

本次验证能证明新分支的行为与安全边界。要证明修复率提高，需要后续在冻结公开案例、相同模型、预算和输入条件下
比较 V2/V3。单个回归案例通过不能推断总体收益。
